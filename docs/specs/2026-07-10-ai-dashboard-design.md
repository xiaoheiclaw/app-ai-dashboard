# AI 赛道看板 — 设计文档

日期:2026-07-10(v2,已吸收 codex challenger 意见)
状态:待用户审阅
项目:`app-ai-dashboard`(新建 GitHub repo,GitHub Pages 公网部署)

## 0. 判准(整个看板的正当性轴)

**这不是 AI 知识地图,是投资假设更新器。**

每个模块、每张卡、每条事件,必须能回答一句话:**"这改变了哪条投资假设?"** 答不上来的内容降级或不进看板。四条被追踪的假设域:能力曲线 / 瓶颈租金 / 资本回报 / 公司脆弱度。

## 1. 目标与定位

AI 赛道的个人投研看板:

- **监控台**:打开看"有什么改变了假设"——10 秒扫完总览
- **假设地图**:已有深度研究(20+ 张 Avibe 深度页)不做"入口导航",而是抽出每张页的**当前假设 + 关键数字 + 失效条件**内嵌进对应板块

核心用户 = 用户本人(投资决策辅助),手机 + 桌面都要能看。

## 2. 整体架构

- **Repo**:`app-ai-dashboard`,私有,挂个人 GitHub 账号(DT-W0202),本地路径 `~/Projects/app-ai-dashboard`
- **技术栈**:Vite + React + TypeScript 静态单页应用
- **部署**:GitHub Pages(私有 repo 经 Actions 发布公开页面),push 即自动部署,页面公网可见(用户已确认接受公开)
- **数据**:全部在 `data/*.json`,运行时 fetch。**更新 = 改 JSON + push = 自动重部署**;git log 即变更审计史
- **UI 骨架**:顶部「本周假设变化」总览横幅 + 三个 tab:模型进展 / 产业链瓶颈 / 资本回报与公司脆弱度
- **认识论约定**:沿用 claim 三分类,关键判断标注 事实/推理/推测

三个 tab 的边界(防止互相吞):
- **模型进展** = 能力与单位智能成本(投资分子的物理基础)
- **产业链瓶颈** = 实物链条的短缺与利润池迁移(应用与收入端也在这里,作为链条终端)
- **资本回报** = 钱从哪来、回不回得来、谁先断(CapEx 是产业链瓶颈 × 公司财务压力的交叉结果,单独成 tab 是因为它是用户的主论题,信息密度足够)

## 3. 板块设计

### 3.1 模型进展(升级现有 demo,组织轴从"日历"换成"问题")

> 设计依据:2026-07-10 调研(Epoch AI / Artificial Analysis / METR / Arena / SemiAnalysis / GS / 独立评论者)。专业追踪者围绕"问题和曲线"组织,不围绕"发布事件";单一 benchmark 寿命 1-2 年,合成指数成主流;投研共识已从"scaling 撞墙没"转到"可靠性 + 单位经济"。

**第一屏:6 个常青问题**,每个问题一个区块 = 曲线 + 当前答案(一句话)+ claim 标注:

| # | 问题 | 曲线/指标 | 口径说明 | 数据源 |
|---|---|---|---|---|
| 1 | Agent 自主时长还在翻倍吗? | METR time-horizon 曲线(对数轴) | 标注"测量近饱和"警告 | METR 公开数据 |
| 2 | 综合智能还在涨吗? | Epoch ECI / AA 智能指数 frontier-over-time | 展示合成指数的成分构成,防黑箱权威 | Epoch CSV / AA |
| 3 | 智能单价降多快? | 价格×性能前沿散点 + 同能力档位价格下降曲线 | 输出直接作为资本回报板块计算器的分子端参考 | Artificial Analysis |
| 4 | 可靠性追上生产要求了吗? | **定性卡片,不画假曲线** | 当前无稳定量化口径(lab-vs-生产落差、N-run 一致性均未标准化);等口径成熟再升级为曲线 | 论文/报告,手动 |
| 5 | 开源/中国模型的商业侵蚀有多快? | 两条**分开标注**的线:①能力差距 = Epoch 滞后月数 ②使用侵蚀 = OpenRouter 中国模型 token 份额 | 明示:份额≠能力,它混含价格/分发/偏好;两指标不得互相替换 | Epoch / OpenRouter |
| 6 | 模型范式正把硬件需求推向哪? | token intensity(每任务 token 数)、推理 vs 训练算力占比、内存 vs 逻辑芯片支出比 | 产业链瓶颈迁移的**需求端解释器**:产业链看"瓶颈在哪",本问看"瓶颈为什么往那去"(推理时算力→推理、长上下文/KV cache→内存、MoE→带宽、FP4→效率) | SemiAnalysis / 财报 / 部分手动 |

**第二屏:事件层**——现有"大模型发布日历 + 技术突破轴"demo(`ses5z98nxwktk`)迁入,但**准入规则收紧**:
- 事件进主板的资格 = 能挂到"6 问之一 / 某环节瓶颈状态 / 某条回本假设"(`affects` 字段非空)
- 挂不上的进折叠的「未分类缓冲区」,不占主板视野;缓冲区积压本身是"该事件不重要"的证据,定期清理

**第三块:争论追踪**——准入规则同上:只收"胜负会改变 6 问答案"的争论(benchmark 污染、scaling 碎轴、benchmaxx 质疑…)。每条:正方证据 / 反方证据 / 当前判断(标 claim)/ 更新日期。不做观点收藏夹。

### 3.2 产业链瓶颈(全新,核心视图 = 瓶颈迁移地图)

核心问题:**瓶颈现在卡在哪一环、谁拥有瓶颈、瓶颈往哪迁移**。

- **链条**:芯片设计 → 晶圆代工 → HBM/存储 → 先进封装 → 服务器/网络 → 数据中心 → 电力 → 云/算力租赁 → 应用与收入
- **每环节预先固定 1-2 个核心指标口径**(实施阶段第 3 步研究定稿),例如:HBM=合约价 / CoWoS=交期 / 电力=并网排队年限 / 云=GPU 租赁价。状态灯规则绑定固定指标,不做"能拿到什么放什么"
- 每个环节一张卡:
  - 瓶颈状态灯:🔴 卡死 / 🟡 紧张 / 🟢 宽松 —— **只表示该环节相对自身历史的紧张度,不跨环节比较绝对值**(各环节口径天然不同,页面明示这一点)
  - **状态灯 ≠ 投资建议**。另设两个分离字段:「谁拥有瓶颈」(标的)与「是否已 priced in」(估值状态,标 claim 类型)——卡死不等于可投,宽松不等于利空
  - 状态依据:一句话 + claim 标注 + 更新日期
- **瓶颈迁移轨迹**:状态变更历史时间轴(如 CoWoS→HBM→电力→内存),可回放——回答"下一个瓶颈在哪"
- 初始状态 + 各环节指标口径需要一轮专项研究定稿(实施阶段第 3 步,产出过 challenger)

### 3.3 资本回报与公司脆弱度(整合现有资产)

- **宏观锚**(板块头部,独立区):GS 口径(~$500B/年 capex 需 >$1T 年利润维持 ROIC)、capex/OCF、D&A/收入趋势。**明示:宏观锚不下压到单家公司判断**——公司卡只用公司自身参数
- **回本压力计算器**:现有 demo(`seszvwuyf3szx`)整体迁入为子页(公司无关的机制层工具)
- **公司卡片,按风险类型分三层,不平铺**:
  1. **超大云厂**(MSFT/GOOGL/META/AMZN/ORCL):核心问题 = ROI 兑现。卡片字段:capex/OCF、backlog/RPO 增速、D&A 拖累、当前假设与失效条件
  2. **Neocloud**(CRWV/NBIS/Crusoe/Lambda/Nscale):核心问题 = 融资与信用脆弱性。字段:债务结构、客户集中度、GPU 抵押条款、下一个融资窗口
  3. **薄资本中介**(Fluidstack 类):核心问题 = 单点依赖。字段:背书方、传染路径
  - 每张卡内容从既有 12 张深度页提炼:**当前假设 + 关键数字 + 失效条件**(不是"结论摘要")
- **capex 事件流**:准入规则同 3.1——必须挂到某条回本假设或某张公司卡

## 4. 数据流与更新机制(三层,不是二层)

> challenger 指出:"agent 不改判断字段"不等于无判断——选源、筛事件本身就是判断。对策:把隐性判断显性化为"结构化事实"层,并在 prompt 里固定数据源清单。

```
① 原始事实层(全自动,零判断裁量)
   固定源清单:Epoch CSV / AA / METR / OpenRouter 公开数据 → 更新曲线 JSON
   Scanner DB + 固定搜索口径 → 候选事件进缓冲区
   源清单变更 = 判断层操作,须人确认

② 结构化事实层(agent 轻判断,全部带 auto 徽章)
   对缓冲区事件做候选归因:建议 affects = 哪一问/哪一环节/哪条假设 + 置信度
   只是"建议",UI 上标 [auto·待确认],与人确认过的视觉区分

③ 判断结论层(人在环,用户触发)
   确认/否决 auto 归因、改状态灯、改争论判断、改公司卡假设
   agent 永不自动改:状态灯、当前答案、假设与失效条件
```

- 自动更新 → git commit + push → Pages 自动部署 → IM 发摘要;失败(源改版等)→ IM 报错,不静默跳过
- commit message 规范:`data(auto):` / `struct(auto):` / `judge:`,diff 即审计
- 事实层频率:初始每日一次(工作日),上线后按噪音水平调

## 5. 实施顺序

1. repo + Vite 骨架 + GitHub Pages 部署跑通(先有能打开的 URL)
2. 模型进展板块:6 问曲线(先用调研快照数据)+ 事件层迁移(带准入规则)+ 争论块
3. 产业链瓶颈:专项研究定各环节**指标口径 + 初始状态**(过 challenger)→ 实现
4. 资本回报板块:迁计算器 + 三层公司卡(从 12 张深度页提炼假设/失效条件)+ 事件流
5. agent 定时任务(vibe task)+ 更新 prompt 上线

每步交付后可用,不需要全部完成才能看。
